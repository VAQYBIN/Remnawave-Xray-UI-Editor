# Xray UI Editor для Remnawave — дизайн

Дата: 2026-07-20
Статус: одобрен пользователем (брейнсторминг завершён)

## Цель

Веб-инструмент для визуального создания и редактирования Xray-конфигов
(конфиг-профилей) панели Remnawave v2.8.0. Пользователь видит топологию
трафика своих конфигов как граф, редактирует её визуально с минимумом
ручного JSON и сохраняет результат напрямую в панель по API.

Вдохновение: https://github.com/bropines/xray-config-ui-editor
(React Flow топология, двухрежимное редактирование). Код пишется с нуля.

## Ключевые решения (из брейнсторминга)

| Вопрос | Решение |
|---|---|
| База кода | С нуля; референс — только вдохновение |
| Скоуп API | CRUD конфиг-профилей + чтение нод/сквадов/inbounds для контекста |
| Доступ | Логин по паролю; токен Remnawave в `.env`, в браузер не попадает |
| UX графа | Гибрид: интерактивный холст + панели-формы для деталей |
| Протоколы | Поэтапно: формы для основного стека, JSON-fallback для всего |
| Язык UI | Русский |
| Архитектура | SPA + лёгкий бэкенд-прокси, один контейнер, Docker Compose |

## 1. Архитектура и стек

Монорепозиторий, два пакета:

```
xray-ui-editor/
├── frontend/          # React 18 + Vite + TypeScript
│   └── src/
│       ├── features/  # topology, inbound-editor, outbound-editor,
│       │              # routing, dns, profiles, auth
│       ├── entities/  # типы Xray-конфига, Zod-схемы
│       └── shared/    # UI-кит, API-клиент
├── backend/           # Node 22 + Fastify + TypeScript
│   └── src/
│       ├── auth/      # логин по паролю, сессии (httpOnly cookie)
│       ├── remnawave/ # типизированный клиент Remnawave API
│       └── routes/    # /api/* — прокси и собственные эндпоинты
├── docker-compose.yml # один сервис app, порт + .env + том ./data
└── Dockerfile         # multi-stage: сборка фронта → рантайм Fastify
```

- Фронтенд: React Flow (`@xyflow/react`) — топология; Zustand — состояние
  конфига; CodeMirror 6 — JSON-панели; TanStack Query — запросы к бэкенду.
- Бэкенд: Fastify раздаёт статику SPA и проксирует `/api/remnawave/*`
  в панель, добавляя `Authorization: Bearer <REMNAWAVE_TOKEN>`.
  Токен и адрес панели существуют только на сервере.
- Авторизация: `APP_PASSWORD` в `.env` (plain или bcrypt-хэш —
  распознаётся по префиксу `$2`), сессия — подписанная httpOnly-cookie
  (`SESSION_SECRET`), rate-limit на `/api/auth/login`.

## 2. Модель данных и валидация

- Единый источник правды — объект Xray-конфига (тот же JSON, что хранит
  панель). Граф, формы и raw-JSON — три представления одной модели
  в Zustand-сторе; изменение в любом мгновенно отражается в остальных.
- Zod-схемы конфига Xray в объёме Remnawave v2.8.0:
  - inbounds: VLESS, Trojan, Shadowsocks — полные схемы; остальные
    (VMess, Dokodemo, SOCKS, HTTP…) — passthrough;
  - streamSettings: tcp/ws/grpc/httpupgrade/xhttp; security: reality/tls/none;
  - outbounds: freedom, blackhole, wireguard (WARP), vless (цепочки),
    остальные — passthrough;
  - routing rules, DNS, sniffing, policy, log.
- Passthrough-принцип: неизвестные поля никогда не теряются — сохраняются
  как есть и доступны через JSON-панель. Инвариант round-trip:
  «загрузил → не менял → сохранил» даёт идентичный JSON.
- Черновики: правки живут в Zustand + localStorage до явного
  «Сохранить в панель». Перед сохранением — diff-превью изменений.

## 3. UI/UX

Три экрана:

1. **Вход** — форма пароля.
2. **Список профилей** — карточки конфиг-профилей: имя, число inbounds,
   привязанные ноды, дата обновления. «Открыть» / «Создать» (пустой или
   из пресета: VLESS+Reality нода; нода с WARP-маршрутизацией и т.п.).
3. **Редактор профиля**:
   - Центр — холст React Flow. Колонки: Скво́ды → Inbounds →
     Routing-правила → Outbounds. Рёбра — потоки трафика; DNS и sniffing —
     отдельные компактные узлы. Автолейаут (dagre/elk), ручные позиции
     запоминаются (localStorage).
   - Узлы информативны: inbound показывает протокол/порт/транспорт/
     security и число сквадов; outbound — тип и назначение; правило —
     сводку условий.
   - Клик по узлу → правая панель-форма: типизированные поля, генератор
     ключей Reality (x25519, shortIds), русские подсказки; вкладка «JSON»
     этого узла.
   - Добавление: «+» на холсте/тулбаре → тип узла → форма. Перетаскивание
     ребра inbound→outbound создаёт routing-правило.
   - Нижняя выдвижная панель — raw JSON всего конфига (CodeMirror,
     двусторонняя синхронизация).
   - Тулбар: Сохранить в панель (diff), Откатить к версии панели,
     Валидация, Экспорт/Импорт файла, Бэкапы.
- Тёмная тема как основная; визуальный стиль прорабатывается скиллом
  frontend-design на этапе реализации. Весь UI на русском.

## 4. Интеграция с Remnawave

- Эндпоинты v2.8.0: `GET/POST/PATCH /api/config-profiles`,
  `GET /api/config-profiles/{uuid}` (+`/inbounds`, `/computed-config`),
  `GET /api/nodes`, `GET /api/internal-squads`.
- Ошибки панели пробрасываются в UI с человекочитаемым текстом.
- Конфликт-детект: при открытии запоминается `updatedAt`; перед
  сохранением профиль перечитывается — если изменён извне, показывается
  предупреждение с diff вместо молчаливой перезаписи.
- Автобэкап: перед каждым PATCH предыдущая версия сохраняется в
  `./data/backups/<profileUuid>/<timestamp>.json` (том Docker).
  Бэкапы видны в UI, восстановление в один клик.
- Сохранение в панель — только явное действие пользователя.

## 5. Обработка ошибок

- Валидация в три уровня: поля (Zod, мгновенно) → целостность конфига
  (висячие ссылки на теги, дубликаты тегов, конфликты портов — подсветка
  узлов на графе) → финальная проверка перед сохранением (блокирует
  отправку, но есть «Сохранить всё равно» — панель финальный арбитр).
- Сетевые ошибки (панель недоступна, токен невалиден, 4xx/5xx) —
  сообщения на русском с деталями ответа; черновик не теряется.
- Истёкшая сессия — редирект на логин, черновик сохраняется.

## 6. Тестирование

- Unit (Vitest): Zod-схемы (валид/невалид, passthrough round-trip),
  конфиг ⇄ граф, генератор Reality-ключей.
- Backend (Vitest + fastify.inject): авторизация, прокси с мок-панелью,
  конфликт-детект, бэкапы.
- Смоук E2E (Playwright): логин → открыть профиль → изменить порт →
  diff → сохранить (против мок-сервера панели).
- Процесс — TDD.

## 7. Деплой

- `docker compose up -d`; один сервис `app`.
- Dockerfile multi-stage: сборка фронта → node:22-alpine рантайм.
- `.env.example`: `REMNAWAVE_URL`, `REMNAWAVE_TOKEN`, `APP_PASSWORD`,
  `SESSION_SECRET`, `PORT`.
- Том `./data` — бэкапы. Healthcheck. Пример reverse-proxy (Caddy) —
  в README, вне скоупа приложения.

## Вне скоупа первой версии

- Управление нодами, хостами, пользователями и сквадами (остаётся в панели).
- Формы для экзотических протоколов (VMess, Dokodemo и др.) — редактируются
  через JSON-панель; формы добавляются поэтапно после первого релиза.
- i18n (только русский), мультипользовательность, HTTPS-терминация.
