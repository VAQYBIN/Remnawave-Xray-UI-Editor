# Балансеры и обсерватория — дизайн

Балансировка нагрузки в топологии: узел балансера между правилами и outbound'ами, глобальная
секция проверки живости отдельным узлом, валидации связки «стратегия ↔ обсерватория»,
трассировка до списка кандидатов и рецепт, собирающий всё это одним действием.

## Задача

Балансеры — единственная часть `routing`, которую редактор не понимает. Схема пропускает их
насквозь (`balancers: z.array(obj())`), граф о них не знает, форм нет. Пользователь, у которого
несколько однотипных апстримов, вынужден писать `routing.balancers` и `observatory` руками в
JSON-вкладке — то есть ровно в том режиме, от которого проект уходит.

При этом фундамент уже лежит: `analyzeIntegrity` ловит висячий `balancerTag`
(`config.ts:126`), `retagInPlace` тащит переименование тега в `selector` и `fallbackTag`
(`mutations.ts:58`), `TracePanel` печатает имя балансера. Не хватает модели, графа, форм и
валидаций.

## Домен: что говорит Xray

Проверено по документации (`xtls.github.io/ru/config/routing.html`, `.../observatory.html`):

```json
{ "tag": "balancer", "selector": [], "fallbackTag": "outbound", "strategy": {} }
{ "type": "roundRobin", "settings": {} }
```

- Стратегии: `random`, `roundRobin`, `leastPing`, `leastLoad`. Первые две работают сами,
  `leastPing` требует `observatory`, `leastLoad` — `burstObservatory`.
- **`selector` матчит теги outbound'ов по префиксу**: `["proxy-"]` захватывает `proxy-de` и
  `proxy-nl`. Это же верно для `subjectSelector` обсерваторий.
- **Если у правила заданы и `outboundTag`, и `balancerTag`, действует `outboundTag`** —
  балансер молча игнорируется.
- `observatory` = `{ subjectSelector, probeUrl, probeInterval, enableConcurrency }`.
- `burstObservatory` = `{ subjectSelector, pingConfig{ destination, connectivity, interval,
  sampling, timeout, httpMethod } }`.
- Обе секции **глобальны**: по одной на конфиг, независимо от числа балансеров.

## Модель данных

Новый `entities/xray/balancers.ts`:

```ts
BalancerSchema = { tag: string, selector?: string[], fallbackTag?: string,
                   strategy?: { type?: 'random'|'roundRobin'|'leastPing'|'leastLoad',
                                settings?: passthrough } }.passthrough()
```

`RoutingSchema.balancers` меняется с `z.array(obj())` на `z.array(BalancerSchema)`.

Новый `entities/xray/observatory.ts` — `ObservatorySchema` и `BurstObservatorySchema` по полям
выше; в `XrayConfigSchema` они заменяют нынешние `obj()`. Везде `passthrough`: незнакомые поля
из чужих конфигов не должны теряться при обратной записи.

Ключевая чистая функция, там же:

```ts
balancerCandidates(config: XrayConfig, balancer: Balancer): string[]
```

Возвращает теги outbound'ов, чей `tag` начинается с любого элемента `selector`. Это
**единственное** место, где живёт правило префикса; её потребляют граф, форма, валидации,
трассировка и рецепт. Расхождение «показано одно, посчитано другое» становится невозможным по
построению.

Рядом — `expandSelector(config, balancerTag, dropTag)`: заменяет префиксы точными тегами
текущих кандидатов и убирает `dropTag`. Нужна разрыву ребра (см. ниже).

## Граф

### Колонки и узлы

Колонки сдвигаются: `squad -380, inbound 0, rule 430, balancer 860, outbound 1290`.

```
 сквады    inbound      правила     балансеры      outbound
┌──────┐  ┌────────┐  ┌────────┐  ┌──────────┐  ┌─────────┐
│Squad │─→│vless-in│─→│ rule 0 │─→│ ⚖ bal-eu │─→│ proxy-de│
└──────┘  └────────┘  │домен:3 │  │leastPing │╲ └─────────┘
                      └────────┘  │selector: │ ╲┌─────────┐
                      ┌────────┐  │  proxy-  │  →│ proxy-nl│
                      │ rule 1 │─→└──────────┘   └─────────┘
                      └────────┘       ╎          ┌─────────┐
                      ┌────────┐       ╎          │ direct  │
                      │ rule 2 │──────────────────→│(дефолт)│
                      └────────┘  ┌──────────┐    └─────────┘
                                  │ ◉ обсерв.│
                                  └──────────┘
```

- `bal:<tag>` — карточка балансера: тег, стратегия, число кандидатов.
- `obs` — узел глобальной обсерватории под колонкой балансеров, ровно по модели узла `dns`
  (одна секция на конфиг, своё место в графе, своя форма). Узел появляется, когда в конфиге
  есть `observatory` или `burstObservatory`; создать секцию можно кнопкой «Настроить проверку
  живости» в форме балансера со стратегией `leastPing`/`leastLoad` или рецептом. Отдельной
  кнопки в доке у обсерватории нет: вне балансировки она бессмысленна.

Дубликаты тегов балансеров пропускаются при сборке графа — так же, как у inbound/outbound:
одинаковые id узлов ломают React Flow. Сам дубликат ловит валидация.

### Рёбра

| id | смысл | стиль |
|---|---|---|
| `e:rule:<i>->bal:<tag>` | правило ведёт в балансер (`balancerTag`) | обычный |
| `e:bal:<tag>->out:<tag>` | кандидат по `selector` | обычный |
| `e:bal:<tag>->out:<fallbackTag>` | запасной выход | пунктир |
| `e:obs->bal:<tag>` | стратегия зависит от обсерватории | пунктир, только `leastPing`/`leastLoad` |

Ребро fallback отделено стилем сознательно: это не кандидат балансировки, а поведение при
отказе всех кандидатов, и рисовать его так же значило бы врать о числе выходов.

### Коммутация

`isValidConnection` пополняется парами `rule → bal` и `bal → out`. Гнёзда обсерватории закрыты:
её связь с балансером выводится из стратегии, а не задаётся кабелем.

- `setRuleBalancer(config, ruleIndex, balancerTag)` — ставит `balancerTag` и **снимает
  `outboundTag`**: иначе по правилам Xray балансер не сработает вовсе.
- `setRuleOutbound` симметрично снимает `balancerTag`.
- Ребро `bal → out` добавляет **точный тег** в `selector`.
- `addBalancer(config)` — новый балансер `{ tag, selector: [], strategy: { type: 'roundRobin' } }`
  с уникальным тегом через существующий `uniqueTag`; кнопка «+ Балансер» в доке топологии.

Разрыв ребра `bal → out` неоднозначен, когда кандидат пришёл из префикса: убрать одного, не
переписав `selector`, нельзя. Поэтому `disconnectEdge` при префиксном совпадении возвращает
**тот же** конфиг (как и прочие мутации при отказе), а `TopologyView` показывает подтверждение
«Развернуть префикс „proxy-“ в точные теги и убрать proxy-nl?» и по согласию вызывает
`expandSelector`. Точное совпадение удаляется сразу, без вопросов. Молча переписывать префикс
редактор не будет: пользователь мог задать его намеренно, под будущие теги.

### Смежные правки

- `retagInPlace` получает третий вид — переименование балансера тащится в `rules[].balancerTag`.
- `getNodeJson` / `applyNodeJson` / `removeNode` учат префикс `bal:` и узел `obs`. Удаление
  балансера не чистит ссылающиеся правила — висячую ссылку показывает валидация, как и при
  удалении outbound'а.
- `locate.ts`: пути `routing.balancers.<i>` → `bal:<tag>`, `observatory` и `burstObservatory` →
  `obs`.
- `search.ts`: балансеры находятся по тегу и по названию стратегии.

## Формы

`BalancerForm` (инспектор узла `bal:`): тег, `selector` списком строк, стратегия, `fallbackTag`.
Под `selector` — живой список совпавших outbound'ов из `balancerCandidates`; пустой список
подсвечен как ошибка. Так префикс перестаёт быть догадкой.

При `leastPing`/`leastLoad` форма показывает строку состояния проверки живости: «обсерватории
нет», «есть, но не покрывает proxy-nl», «настроена» — и кнопку перехода к узлу `obs`.
Редактировать глобальную секцию из карточки балансера нельзя: два балансера правили бы одно
поле и затирали друг друга.

`ObservatoryForm` (узел `obs`): две секции — `observatory` и `burstObservatory`, каждая
включается тумблером; поля по схеме, `subjectSelector` — список строк с тем же живым превью
кандидатов.

`strategy.settings` для `leastLoad` (`expected`, `maxRTT`, `tolerance`, `baselines`, `costs`)
формой не редактируется — только через JSON-вкладку узла. Это тонкая настройка для единиц
пользователей, а `costs` с регулярками потянул бы за собой отдельный редактор списка.

## Валидации (`analyzeIntegrity`)

Ошибки (блокируют «Сохранить в панель»):

- дубликат тега балансера; балансер без `tag`;
- `selector` пуст или не матчит ни одного outbound'а — балансер не выберет ничего.

Предупреждения:

- у правила заданы и `outboundTag`, и `balancerTag` — действует `outboundTag`, балансер
  игнорируется;
- висячий `fallbackTag`;
- `leastPing` без `observatory` / `leastLoad` без `burstObservatory`;
- `subjectSelector` обсерватории не покрывает часть кандидатов балансера — эти выходы ядро
  мерить не будет;
- (уже есть) висячий `balancerTag` у правила.

«Стратегия без обсерватории» — предупреждение, а не ошибка: откажется ли ядро стартовать, на
реальном Xray не проверялось, а кнопка «Проверить ядром» уже есть и остаётся источником истины.
Если проверка ядром покажет отказ старта — уровень поднимается до `error` отдельной правкой.

Все проблемы несут `parts` вида `['routing','balancers',i,'selector']` и `['observatory',
'subjectSelector']`, поэтому клик по проблеме работает в обеих вкладках без дополнительного кода.

## Трассировка

`TraceWinner` дополняется полями `balancerCandidates?: string[]` и `balancerStrategy?: string`,
заполняемыми той же `balancerCandidates`. `TracePanel` вместо голого «балансер bal-eu» показывает
стратегию и список кандидатов.

`collectCaveats` добавляет две оговорки:

- «Конкретный выход выбирает ядро в рантайме по замерам — предсказать его нельзя» — всегда,
  когда победило правило с `balancerTag`;
- «У балансера „bal-eu“ нет кандидатов: трафик уйдёт в `fallbackTag` / будет отброшен» — когда
  список кандидатов пуст.

`tracedEdgeIds` подсвечивает путь целиком: входы → правило → балансер → все кандидаты.
Победитель среди кандидатов не выделяется — редактор не знает того, чего не знает.

## Рецепт «Балансировка»

`RecipeId` пополняется значением `balance`, параметры (`BalanceParams`): `tag`, `members:
string[]` (галочки по существующим outbound'ам), `strategy`, `fallbackTag?`, `repoint: boolean`
(«перевести правила, ведущие в выбранные outbound'ы, на балансер»).

`planBalance` собирает: балансер с точными тегами в `selector`; при `leastPing`/`leastLoad` —
обсерваторию нужного вида; при `repoint` — перевод правил.

Два новых примитива в `apply.ts` рядом с `ensureOutbound`/`ensureRule`:

- `ensureBalancer(config, balancer)` — по тегу, статусы `add`/`exists`;
- `ensureObservatory(config, kind, subjects)` — создаёт секцию либо **дополняет**
  `subjectSelector` недостающими тегами, не затирая чужие значения.

И `repointRules(config, outboundTags, balancerTag)` — у правил с подходящим `outboundTag`
ставит `balancerTag` и снимает `outboundTag`.

Идемпотентность как у остальных рецептов: повторное применение даёт `exists` по всем строкам и
тот же объект конфига по ссылке. `validateBalance`: пустой `members`, `fallbackTag` внутри
`members`, тег, уже занятый outbound'ом или другим балансером.

  (и наоборот), переименование балансера тащится в правила, `disconnectEdge` по префиксному
  ребру возвращает тот же конфиг, а после `expandSelector` — убирает кандидата.
- дополнения в `trace.test.ts`: кандидаты в победителе, обе новые оговорки, подсветка рёбер.
- `recipe-balance.test.ts`: план на чистом конфиге, идемпотентность, `repoint`, дополнение

outbound'а → в форме видны оба кандидата → разрыв префиксного ребра через подтверждение.

## Что осознанно не делаем

- **Живые замеры пинга в редакторе** — данные `observatory` живут в рантайме ядра на ноде,
  редактор к ней доступа не имеет; показывать выдуманные цифры хуже, чем не показывать никаких.
- **Форму для `strategy.settings` у `leastLoad`** — см. раздел «Формы».
- **Балансеры для inbound'ов** — в Xray их нет, балансируются только исходящие.
