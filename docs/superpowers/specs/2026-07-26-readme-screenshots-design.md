# Скриншоты интерфейса для README — дизайн

Пять снимков работающего редактора на витринном конфиге, снимаемых одной командой и
встроенных в README так, чтобы человек понимал, что это, не читая ни строки.

## Задача

README описывает редактор словами и не показывает его. Проект визуальный: его главный
аргумент — граф трафика и формы вместо ручного JSON, и оба этих аргумента текстом не
передаются. Человек, зашедший на страницу репозитория, сейчас обязан либо поверить на слово,
либо развернуть приложение у себя — то есть оценить продукт до установки невозможно.

## Решение

Пять кадров, снимаемых Playwright'ом на моках API — без бэкенда, без настоящей панели и без
единого реального токена в кадре.

| Файл | Что на нём | Куда в README |
| --- | --- | --- |
| `topology.png` | граф целиком: сквады → inbound'ы → правила → балансер → outbound'ы, док снизу | под бейджами, герой-кадр |
| `inspector-reality.png` | форма inbound'а с раскрытой Reality-секцией и генератором ключей | «Возможности» |
| `trace.png` | подсвеченный путь трафика, вердикты на правилах, панель разбора | «Диагностика конфига» |
| `recipes.png` | диалог рецепта со списком изменений до применения | «Рецепты» |
| `json-intellisense.png` | вкладка «JSON узла» с открытым списком автоподсказок | «Возможности» |

Герой-кадр стоит сразу под бейджами: до раздела «Возможности» доходит меньше людей, чем до
первого экрана.

## Четвёртый контур, а не расширение e2e

В проекте три непересекающихся контура тестов (vitest, Playwright e2e, `tsc --noEmit`), и это
осознанное правило. Скриншоты становятся четвёртым: каталог `frontend/screenshots/` со своим
`playwright.screenshots.config.ts` и командой `npm run screenshots -w frontend`.

Причина разделения: съёмка пишет файлы в репозиторий и живёт по другому расписанию, чем
тесты. Встроенная в `npm run e2e`, она замедлила бы каждый прогон и на каждом PR порождала бы
diff в бинарных файлах — при том, что ни одно утверждение о корректности она не проверяет.

## Витринный конфиг

`frontend/screenshots/showcase.ts` — конфиг, профиль и сквады.

Минимальный конфиг из `e2e/mocks.ts` для съёмки не годится: один inbound, два outbound и одно
правило дают почти пустой граф. Витринный заполняет все пять колонок:

- **inbounds:** VLESS + Reality + Vision (443), Trojan поверх WebSocket с TLS (8443),
  Hysteria 2 (2096);
- **outbounds:** `direct` (freedom), `block` (blackhole), `warp` (wireguard),
  `proxy-de` и `proxy-nl` (vless);
- **балансер** `foreign` с `selector: ["proxy-"]`, стратегией `leastPing` и секцией
  `observatory` — без неё ядро не стартует, и редактор об этом справедливо ругается;
- **правила:** блокировка рекламы, локальных сетей и торрентов; OpenAI и Google в WARP;
  остальное — на балансер;
- **сквады:** два, приходят не из конфига, а из контекста панели.

**Конфиг обязан давать ноль диагностик.** Значки проблем на герой-кадре читаются как «продукт
сломан», а не как «в примере есть ошибка».

Моки переиспользуются приёмом, уже принятым в репозитории: сначала `mockApi(page)` из
`e2e/mocks.ts`, затем переопределение маршрутов профиля и сквадов — поздний обработчик
Playwright перекрывает ранний.

## Анимации дожидаются, а не отключаются

Обычный приём детерминированной съёмки — глушить анимации инъекцией CSS. **Здесь он сломает
картинку.** У карточек узлов есть входная анимация с задержками по колонкам, а компонент
`RemeasureOnEnter` пересчитывает якоря рёбер по событию `animationend`. Без анимаций событие не
приходит, якоря остаются снятыми со сдвинутых карточек, и на снимке все рёбра оказываются на
8px ниже своих гнёзд — ровно тот дефект, который был найден глазами и закрыт e2e-тестом
`edge-anchors.spec.ts`.

Поэтому съёмка ждёт завершения анимаций и только потом делает кадр.

## Формат файлов

PNG в `docs/screenshots/`, viewport 1440×900 при `deviceScaleFactor: 2` — GitHub отдаёт README
на дисплеях с удвоенной плотностью, и кадр в одинарной оказался бы мылом.

Вес контролируется: если кадр перевалит за ~500 КБ, плотность снижается до 1.5. README не
должен весить как дистрибутив.

## Вне рамок

- **Проверка скриншотов в CI.** Пересъёмка — команда по требованию, когда интерфейс заметно
  меняется. Сравнение пикселей на каждом PR даёт либо хрупкие падения, либо бессмысленный
  прогон.
- Светлая тема: в приложении её нет, тема одна.
- Анимированные GIF и видео: вес и невозможность нормально пересобрать.
- Скриншоты остальных диалогов (Geo-базы, Версии, Проверка ядром) — при желании добавляются
  тем же механизмом позже, отдельным кадром и строкой в README.
