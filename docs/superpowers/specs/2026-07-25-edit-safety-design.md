# Безопасность правок: undo/redo, хоткеи, файл, сравнение версий

Дата: 2026-07-25. Направление 3 фазы 3 (после диагностики конфига и UX-долга).

## Проблема

Черновик правится из четырёх мест — граф, формы инспектора, диалог настроек, JSON-редактор, — но
истории у него нет вовсе. Единственный откат — «Сбросить к версии панели», то есть потеря всей
работы. Удалили узел не тот — восстановить нечем.

Рядом три соседние дыры того же свойства: конфиг нельзя вынести в файл и принести обратно; бэкап
можно только применить вслепую, не посмотрев, чем он отличается от текущего; ни одно частое
действие не имеет клавиатурного пути.

## Решения, принятые при обсуждении

1. **Разделение обязанностей между историей приложения и CodeMirror.** На вкладке JSON `Ctrl+Z`
   остаётся за редактором (посимвольная отмена уже работает), кнопки ↶/↷ там заблокированы.
   История приложения записывает структурные правки, а текстовую сессию сворачивает в один снимок
   при уходе с вкладки. Альтернатива «одна история на всё» (отключить `history()` у CodeMirror,
   склеивать ввод по таймеру) отвергнута: теряется посимвольная отмена, а склейка по времени даёт
   непредсказуемые скачки и снимок конфига на каждую паузу.
2. **История живёт в памяти**, не в `localStorage`. 50 снимков по 10–50 КБ — единицы мегабайт при
   квоте около 5 МБ на origin; персист вытеснил бы сами черновики. История — сессионный инструмент,
   как цель трассировки.
3. **Хоткеи:** `Ctrl+Z`, `Ctrl+Shift+Z`/`Ctrl+Y`, `Ctrl+F`, `Esc`, `?`. `Ctrl+S` сознательно не
   вводим — сохранение остаётся явным действием через диалог с diff.
4. **Размещение:** ↶ ↷ и «?» — компактной группой слева, рядом с переключателем вкладок. Экспорт и
   импорт не добавляют кнопок в правую группу (там уже шесть), а въезжают в диалог бэкапов, который
   становится «Версиями конфига» с двумя вкладками.
5. **Импорт мягкий:** берём всё, что распарсилось в JSON-объект; ошибки схемы показывает обычный
   статус-бар — редактор для этого и сделан, а починка чужого конфига в нём и есть основной сценарий
   импорта. Неудачный импорт откатывается через ↶.

## Архитектура

### История правок

`features/editor/historyStore.ts` — zustand **без** `persist`:

```ts
interface Stack { past: string[]; future: string[] }
interface HistoryState {
  stacks: Record<string, Stack>          // ключ — uuid профиля
  record: (uuid: string, prevText: string) => void   // push в past, future очищается
  undo: (uuid: string, currentText: string) => string | null
  redo: (uuid: string, currentText: string) => string | null
  clear: (uuid: string) => void
}
export const HISTORY_LIMIT = 50
```

`record` кладёт в `past` **предыдущий** текст и очищает `future` (новая ветка правок). При
переполнении вытесняется самый старый снимок. `undo` снимает вершину `past`, толкает `currentText`
в `future` и возвращает снятое; `redo` — зеркально. Если стек пуст, возвращается `null` — на этом
же условии строится `disabled` у кнопок.

В `EditorPage` появляется единственная точка записи черновика вместо разрозненных вызовов
`setDraft`:

```ts
function writeDraft(nextText: string, opts: { history: boolean }) {
  if (opts.history) record(profile.uuid, text)   // text — текущий, ещё не изменённый
  setDraft(profile.uuid, nextText, draft?.baseUpdatedAt ?? profile.updatedAt)
}
```

| Событие | История |
|---|---|
| граф, формы инспектора, «Настройки конфига», перестановка правил, удаление узла (`changeConfig`) | `record` |
| ввод текста в `JsonView` | не пишем — это CodeMirror |
| уход с вкладки JSON, если текст изменился | `record` со снимком, снятым при входе на вкладку |
| восстановление бэкапа, импорт файла | `record` |
| «Сбросить к версии панели» | `record` — сброс тоже отменяется |
| успешное сохранение в панель, «Загрузить версию панели» при конфликте | `clear` — база сместилась, прежние снимки относятся к другому документу |

Снимок вкладки JSON: при переключении на JSON запоминаем текущий текст в `useRef`; при уходе, если
текст отличается, вызываем `record` именно с запомненным значением, а не с текущим.

Сброс к версии панели вызывает `clearDraft`, то есть черновика после него нет вовсе. Отмена этого
шага идёт обычным путём — `undo` возвращает текст из `past` и записывает его через `setDraft`,
создавая черновик заново; `baseUpdatedAt` при этом берётся у профиля, как и при любой другой правке
после сброса.

После `undo`/`redo` конфиг подменяется целиком, поэтому `setSelectedNode(null)` — правило проекта:
позиционные `rule:N` дрейфуют при полной замене документа.

### Хоткеи

`shared/lib/useHotkeys.ts` экспортирует чистые `matchCombo(event, combo)` и `isEditableTarget(el)`
плюс сам хук:

```ts
type Binding = { combo: string; handler: (e: KeyboardEvent) => void; whenEditable?: boolean }
export function useHotkeys(bindings: Binding[]): void
```

Комбинация задаётся строкой: `'mod+z'`, `'mod+shift+z'`, `'mod+y'`, `'mod+f'`, `'Escape'`, `'?'`.
`mod` — это `ctrlKey || metaKey`, платформенных веток не заводим. Обработчик по умолчанию не
срабатывает, когда фокус в `input`, `textarea`, `select` или элементе с `contenteditable` — последнее
покрывает и `.cm-content` CodeMirror. `Escape` дополнительно молчит, когда в документе есть открытый
нативный `<dialog>`: он закроется сам, перехват увёл бы фокус.

Раскладка:

| Сочетание | Действие |
|---|---|
| `Ctrl/Cmd+Z` | отменить (заблокировано на вкладке JSON — там своя история) |
| `Ctrl/Cmd+Shift+Z`, `Ctrl+Y` | вернуть |
| `Ctrl/Cmd+F` | фокус в поиск по конфигу; только на вкладке «Топология», на JSON отдан поиску редактора |
| `Escape` | каскад: инспектор узла → панель разбора трассы → результаты поиска |
| `?` | диалог со шпаргалкой |

`features/editor/ShortcutsDialog.tsx` — статичный список сочетаний. Кнопка «?» в топбаре с
`aria-label="Горячие клавиши"`; без неё о хоткеях никто не узнает.

Фокус в поле поиска: `SearchBox` получает проп `focusSignal: number`, по изменению которого делает
`ref.current?.focus()`. Лезть в DOM по `id` из `EditorPage` не будем.

### Экспорт и импорт

`features/editor/configFile.ts`:

```ts
export function exportFileName(profileName: string, date: Date): string
export function parseImported(text: string): { text: string } | { error: string }
export function downloadJson(text: string, fileName: string): void
```

`exportFileName` заменяет всё, кроме букв, цифр и дефиса, на дефис, схлопывает повторы, обрезает до
60 символов и добавляет дату: `my-profile-2026-07-25.json`. Пустое имя вырождается в `config`.

`parseImported` разбирает JSON и возвращает переформатированный `JSON.stringify(value, null, 2)`.
Отказы: не разбирается как JSON («Файл не разбирается как JSON: …»), значение — массив, строка или
число («Ожидается объект конфига, а в файле …»). Одна поблажка: если у объекта есть `profile.config`
или `config` и это объект — разворачиваем и берём его. Это ровно тот файл, который пользователь
возьмёт из `DATA_DIR/backups`.

`downloadJson` — `Blob` + `URL.createObjectURL` + временная `<a download>` + `revokeObjectURL`.
Побочный эффект изолирован в одной функции, чтобы остальное осталось чистым и тестируемым.

### Диалог «Версии конфига»

`features/editor/DiffView.tsx` — общий компонент сравнения, вынутый из `SaveDialog`:

```tsx
<DiffView original={string} modified={string} maxHeight?: string />
```

Внутри тот же `MergeView` из `@codemirror/merge` с `EditorView.editable.of(false)` и темой на
токенах проекта; вьюха пересоздаётся при смене `original`/`modified` и уничтожается на размонтировании.
`SaveDialog` переходит на него без изменения поведения.

`BackupsDialog.tsx` → `VersionsDialog.tsx`, заголовок «Версии конфига», две вкладки:

- **«Бэкапы панели»** — прежний список, у каждой записи теперь две кнопки: «Сравнить» и «В черновик».
- **«Файл»** — «Скачать JSON» (текущий текст черновика) и «Загрузить из файла»
  (`<input type="file" accept="application/json,.json">`, скрыт за кнопкой). Ошибка импорта выводится
  тут же.

«Сравнить» загружает бэкап и переключает **содержимое того же диалога** в режим сравнения: заголовок
«Бэкап от <дата> ↔ черновик», `DiffView` (слева бэкап, справа текущий черновик — как в `SaveDialog`,
где слева версия панели), кнопки «← К списку» и «В черновик». Вложенный `<dialog>` не заводим: top
layer в этом проекте уже конфликтовал с порталом `Select`.

Если файл вырастает за ~180 строк, список бэкапов выносится в `BackupsList.tsx`; порог проверяется
при реализации.

### Топбар

Слева от переключателя вкладок — группа `.wb-iconbar`: ↶, ↷ и «?». Кнопки квадратные, с `title` и
`aria-label` («Отменить», «Вернуть», «Горячие клавиши»). Правая группа кнопок не растёт: «Бэкапы»
превращается в «Версии», экспорт и импорт живут внутри диалога.

Новые классы в `tokens.css`: `.wb-iconbar`, `.versions-tabs`, `.diff-frame`, `.shortcuts-list` — в
идиоме проекта, на существующих токенах.

## Границы

Не делаем: персист истории между перезагрузками, именованные точки восстановления и просмотр всей
истории списком, копирование конфига в буфер обмена (скачивание файла закрывает потребность),
`Ctrl+S`, выпадающее меню в топбаре, слияние импортируемого конфига с текущим (импорт всегда заменяет
документ целиком).
