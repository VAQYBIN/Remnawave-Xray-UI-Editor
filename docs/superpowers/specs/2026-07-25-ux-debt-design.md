# UX-долг: привязка диагностик, значки проблем и поиск по конфигу

Дата: 2026-07-25. Статус: дизайн утверждён.

## Проблема

Редактор умеет находить проблемы, но не умеет показать, **где** они.

1. **Диагностика не привязана к месту.** Линтер JSON-вкладки отдаёт CodeMirror все проблемы с
   `from: 0, to: 0` (`JsonView.tsx`): маркер всегда на первом символе, подчёркивания нет,
   польза от подсветки нулевая. При этом путь у проблемы есть — просто никто его не разрешает
   в позицию.
2. **Из списка проблем некуда пойти.** `IssueList` — статичный текст. Прочитав
   «`routing.rules.4.domain`: домены без префикса матчатся как подстрока», пользователь ищет
   это правило глазами.
3. **На графе не видно, где беда.** Чтобы узнать, есть ли проблемы у конкретного inbound'а,
   надо развернуть статус-бар и сопоставить путь с узлом вручную.
4. **Найти узел нечем.** На профиле с десятком inbound'ов и двумя десятками правил
   единственный способ найти нужный — прокрутка холста.

## Рамки

**Входит:** путь диагностики массивом (`parts`); разрешение пути в диапазон символов JSON;
настоящие диапазоны в линтере; клик по проблеме — умный переход по вкладке (узел или курсор);
значки ошибок/предупреждений на узлах графа; поиск узлов по конфигу со списком результатов и
центрированием.

**Не входит:** подсветка конкретного поля **внутри формы** инспектора (формы написаны руками,
реестра полей нет — работа несоразмерного объёма); фильтрация графа по поиску (ломает связность,
ради которой граф и нужен); собственный поиск на вкладке JSON (штатный `Ctrl+F` CodeMirror уже
работает — `basicSetup` включён по умолчанию и приносит `@codemirror/search`); undo/redo и
хоткеи (это следующее направление).

## Принятые решения

1. **Путь — массив, строка производна.** `ValidationIssue` получает
   `parts: (string | number)[]`, а `path` остаётся строкой для показа и собирается из `parts`.
   Zod уже отдаёт путь массивом, так что для схемных ошибок это ноль работы. Строку сохраняем,
   потому что на неё опираются существующие тесты и статус-бар, а склейка через точку
   неоднозначна на ключах, которые сами содержат точку (`dns.hosts` с ключом `example.com`).
2. **Резолверы — чистые функции в слоях, а не в компонентах.** Путь → диапазон живёт во
   `features/editor` (нужен `EditorState` CodeMirror), путь → узел и счётчики проблем — в
   `entities/graph` (он владеет схемой id), поиск — там же.
3. **Не находится — значит не находится.** Если путь не разрешается (текст правится и дерево
   разъехалось), поведение разное по назначению, но одинаково честное: линтер обязан отдать
   CodeMirror какой-то диапазон, поэтому ставит его в начало документа и прямо пишет в тексте,
   что место не определено; клик по такой проблеме недоступен. Молча ставить курсор
   «куда-нибудь» хуже, чем не ставить вовсе.
4. **Вкладку не переключаем.** Клик по проблеме работает в контексте текущей вкладки. Часть
   проблем (`log`, `policy`) вообще не имеет узла — насильный переход на топологию привёл бы в
   никуда.

## Дизайн

### 1. Путь диагностики (`entities/xray/config.ts`)

```ts
export type PathParts = (string | number)[]

export interface ValidationIssue {
  parts: PathParts
  /** Производное от parts представление для показа и сортировки */
  path: string
  message: string
  level: 'error' | 'warning'
}

export function formatPath(parts: PathParts): string  // parts.join('.')
```

`analyzeIntegrity` строит `parts` (двадцать мест конструирования), `path` проставляется одним
хелпером `issue(parts, message, level)`. Для zod-ошибок `parts` — это `i.path` как есть.
Формат строки не меняется, поэтому существующие тесты (`i.path === 'inbounds.0.streamSettings'`)
остаются зелёными — это и есть проверка, что перевод сделан без смещения смысла.

### 2. Путь → место в JSON (`features/editor/jsonLocate.ts`)

```ts
locateRange(state: EditorState, parts: PathParts): { from: number; to: number } | null
```

Спуск по синтаксическому дереву CodeMirror: на объекте ищем `Property` с нужным именем ключа,
на массиве — элемент по индексу. Существующий `intellisense/context.ts` ходит в обратную
сторону (позиция → путь) и переиспользован быть не может, но общие мелочи (`stripQuotes`,
чтение имени `Property`) выносятся в него и импортируются, чтобы не держать две копии.

Диапазон возвращается **на значение** свойства, а не на весь `Property`: подчёркивание должно
показывать `"reality"`, а не `"security": "reality"`. Если последний сегмент не найден, но
найден его родитель — отдаём диапазон родителя: у ошибки уровня `inbounds.0.streamSettings`
конкретного ключа и нет, а у `inbounds.0.settings.flow` при отсутствующем `flow` разумно
подсветить `settings`.

Потребители:
- **линтер** (`xrayLinter` в `JsonView.tsx`) — вместо `from: 0, to: 0` подставляет найденный
  диапазон; ненайденное отдаёт диагностику на первой строке документа, но помеченную как
  «место не определено» в тексте сообщения, чтобы маркер не врал о позиции;
- **переход по клику** — `JsonView` получает проп `reveal: { parts: PathParts; nonce: number } | null`
  и в эффекте прокручивает к диапазону и ставит выделение. `nonce` нужен, чтобы повторный клик
  по той же проблеме снова прокручивал; ссылка на `EditorView` берётся через `onCreateEditor`.

### 3. Путь → узел графа (`entities/graph/locate.ts`)

```ts
nodeIdForPath(parts: PathParts, config: XrayConfig): string | null
issueCountsByNode(issues: ValidationIssue[], config: XrayConfig): Record<string, IssueCount>
```

Соответствие: `inbounds.N.*` → `in:<tag>`, `outbounds.N.*` → `out:<tag>`, `routing.rules.N.*` →
`rule:N`, `dns.*` → `dns`. Остальное — `null`. Теги берутся из конфига по индексу, потому что
id узлов строятся по тегу; при дубликатах тегов (`buildGraph` их пропускает) первый узел и
получает счётчик — это согласовано с тем, что рисует граф.

`IssueCount` — `{ errors: number; warnings: number }`. Узел с ошибками показывает бейдж
уровня error, иначе warning; число выводится, когда проблем больше одной.

**Ограничение по перерисовке (усвоено на этапе 2 диагностики):** счётчики прокидываются в
`TopologyView` отдельным пропом и доклеиваются к узлам **вторым** `useMemo`, а не участвуют в
том, что вызывает `buildGraph`. Иначе каждая правка пересоздаёт все узлы, и они пропадают под
анимацией появления.

### 4. Клик по проблеме

`IssueList` получает необязательный `onSelect(issue)` и рендерит строку кнопкой только тогда,
когда переход возможен. Решение принимает `EditorPage`:

- вкладка «Топология»: `nodeIdForPath` → `setSelectedNode`; узел выделяется, инспектор
  открывается. Если узла нет — строка не кликабельна;
- вкладка «JSON»: `setReveal({ parts, nonce })` → прокрутка и выделение диапазона.

### 5. Поиск (`entities/graph/search.ts` + `features/topology/SearchBox.tsx`)

```ts
searchNodes(config: XrayConfig, ctx: GraphContext, query: string): SearchHit[]
// SearchHit: { nodeId, kind: 'inbound'|'outbound'|'rule'|'squad'|'dns', title, matchedOn }
```

Ищем подстрокой без учёта регистра по: тегам inbound/outbound, протоколу, порту, именам
сквадов, а у правил — по `outboundTag`, доменам, IP и портам. `matchedOn` объясняет совпадение
(«домен: geosite:google»), иначе в списке из десятка правил непонятно, почему они там.
Результаты ограничены двадцатью — длиннее список бесполезен, а запрос надо уточнять.

UI: строка в доке рядом с тумблером «Трасса», выпадающий список, выбор → `EditorPage`
выделяет узел, `TopologyView` центрирует его (`setCenter` из `useReactFlow`, тот же хук, что уже
используется для сохранения вьюпорта). Пустой запрос — списка нет.

### 6. Тестирование

- **vitest (entities):** `locateRange` — вложенные объекты, элементы массивов, ключ с точкой
  внутри, отсутствующий путь → `null`, откат на родителя; `nodeIdForPath` — все четыре ветки
  и `null` для `log`; `issueCountsByNode` — ошибки перевешивают предупреждения, дубликаты
  тегов; `searchNodes` — совпадения по тегу/порту/домену, регистр, лимит.
- **vitest (компоненты):** `IssueList` — клик зовёт `onSelect`, строка без узла не кнопка;
  `JsonView` — `reveal` прокручивает и выделяет, повтор с новым `nonce` срабатывает снова.
- **Playwright:** клик по проблеме на топологии открывает инспектор нужного узла; на вкладке
  JSON — ставит выделение; поиск по тегу центрирует и открывает узел; узел с ошибкой показывает
  бейдж.

## Границы и риски

- Диапазон разрешается по **текущему** тексту редактора. Пока пользователь печатает, дерево
  временно невалидно, и часть диагностик окажется без места — это видно как отсутствие
  подчёркивания, а не как ошибка.
- Соответствие «путь → узел» держится на схеме id из `buildGraph`. Если схема изменится,
  сломается переход, а не отрисовка — тесты `nodeIdForPath` ловят это сразу.
- Поиск не ищет по полям, которых нет в графе (например, по содержимому `policy`), — для этого
  на вкладке JSON есть штатный `Ctrl+F`.
