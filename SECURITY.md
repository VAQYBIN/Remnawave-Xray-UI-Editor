# Политика безопасности

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Отчёт идёт через приватный канал GitHub:

**Security → Advisories → [Report a vulnerability](https://github.com/VAQYBIN/Remnawave-Xray-UI-Editor/security/advisories/new)**

Переписка видна только вам и мейнтейнеру, пока адвайзори не опубликован.

Что приложить: версию (коммит или тег), способ развёртывания (Docker / из исходников),
шаги воспроизведения, наблюдаемый и ожидаемый результат. Работающий PoC ускоряет разбор.

Ответ — в течение 72 часов. Дальше: подтверждение или обоснованный отказ, исправление в
приватной ветке, публикация адвайзори с указанием автора отчёта (если он не против).
Проект ведёт один мейнтейнер, поэтому сроки исправления зависят от сложности — статус
сообщается в переписке.

## Поддерживаемые версии

Исправления выходят только для текущего состояния ветки `main`. Отдельных
поддерживаемых веток и бэкпортов нет: обновляйтесь на `main`.

## Модель угроз

Редактор — тонкий прокси к API панели Remnawave. Ценность для атакующего сосредоточена
в двух местах:

- **`.env`** — `REMNAWAVE_TOKEN` (полный доступ к панели), `SESSION_SECRET`, `APP_PASSWORD`.
- **`DATA_DIR/backups/`** — бэкапы конфиг-профилей: приватные ключи Reality, ключи
  WireGuard/WARP, UUID пользователей.

Компрометация любого из них равнозначна компрометации самой панели, а не только редактора.

### Считается уязвимостью

- Обход аутентификации или подделка сессионной cookie; обход rate-limit на логине.
- Утечка токена панели или содержимого `.env` в браузер, ответы API или логи.
- Обход `net/guard.ts` — SSRF через ссылки на geo-базы, Reality-пробу или регистрацию WARP
  (включая редиректы на приватные, loopback, link-local и CGNAT-адреса).
- Выход за `DATA_DIR` при чтении или записи бэкапов и настроек (path traversal).
- Инъекция аргументов или команд в вызов `xray run -test`.
- XSS в редакторе, позволяющий действовать от имени вошедшего пользователя.
- Отдача файлов за пределами `STATIC_DIR`.

### Не считается уязвимостью

- Публикация порта приложения в интернет напрямую, без HTTPS-прокси. Сессионная cookie
  идёт без флага `secure` — это документировано в README, ставьте Caddy/nginx или firewall.
- Слабый или общий с кем-то `APP_PASSWORD`, утёкший файл `.env`, доступ к каталогу `data/`
  на хосте: аутентификация в редакторе одноуровневая, ролей и аудита нет by design.
- Возможность вошедшего пользователя записать в профиль произвольный Xray-конфиг — это и
  есть назначение приложения.
- `GEO_ALLOW_PRIVATE_URLS=true` открывает доступ во внутреннюю сеть: это осознанный опт-ин
  со своим предупреждением в `.env.example`.
- Уязвимости самого Xray-core, панели Remnawave или их API — сообщайте в соответствующие
  проекты.
- Отчёты сканеров без демонстрации эксплуатации, отсутствие security-заголовков на
  статике, версии зависимостей без известного вектора в этом коде.
